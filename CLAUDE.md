# CLAUDE.md

## Project

walx is a standalone Go executable (`cmd/walx`) that turns the Postgres WAL (pgoutput, Postgres 18+ only) into an ordered, at-least-once event stream written to a sink. One `config.yaml` lists several databases; each gets an independent pipeline (connection, slot, sink, retry, LSN checkpoint). No public Go API, no user Go code.

Status: M1 to M4 and the sink registry, contract suite, stdout and file sinks are implemented: config, `internal/event`, `internal/postgres` (connection, slot, publication, stream, standby, relation cache, pgoutput decoding, transaction buffering, schema change, `EnsureReplicaIdentity`, `ReadKeys`, `CheckKeys`, `CheckWALRetention`), `internal/engine` (run loop, retry, permanent errors, idle advance, shutdown, reconnect via `Config.NewSource`, supervisor) and all `internal/filter` rules. The postgres integration tests run against a real Postgres 18 (see Commands). Not started: the NATS sink and metrics. `cmd/walx` is still a snapshot stub: wiring the engine, the startup checks (the identity, key and WAL retention checks) and the first source is pending (T6.2).

## Architecture rules

- A sink returns `nil` only when the batch is durable at the destination; only then does the engine confirm the batch's `EndLSN`. Retry, idle advance and shutdown follow from this.
- Every package except `cmd/walx` lives under `internal/`; each sink in `internal/sink/<name>`.
- `internal/event` holds the shared types (`Event`, `Batch`, `Op`, `Sink`, `Metrics`, `Unchanged`, `Permanent`). Engine code depends on the `event.Metrics` interface, never a concrete metrics package.
- `Event.ID` is `<name>-<commitLSN>-<seq>`, with `seq` counted over the raw transaction before filters, so IDs stay stable across redelivery and config changes.
- Delivery is serial and in WAL order within one database; no ordering across databases. Fail fast: one pipeline stopping shuts the others down and exits non-zero.
- Filters must not mutate shared events; copy first.
- Config: yaml `Node.Decode` ignores `KnownFields`, so `internal/config/keys.go` rejects unknown keys itself, before defaults and decoding.
- Config: YAML aliases and merge keys are rejected (they would skip env expansion and key checks). `${VAR}` expansion clears the `!!str` tag of changed plain scalars so bool and int fields work; quoted scalars stay strings. In YAML tests write `${VAR}` in block style, since `{` breaks flow mappings.
- Config: database names match `^[a-z][a-z0-9_]{0,57}$` (58 chars, so `walx_<name>` fits 63) and slots `[a-z_][a-z0-9_]{0,62}` (a leading digit breaks CREATE_REPLICATION_SLOT), since the name feeds the default slot, publication and `Event.ID`. Duplicate ops in a table are rejected; `serverOf` falls back to the `host` query parameter for unix-socket URLs. A config holds one YAML document and no null list items (yaml would drop them and shift error indexes).
- CLI: `cmd/walx` logic lives in `run(args, stdout, stderr) int` so exit codes and messages are testable; exit 2 for usage errors, 1 for runtime errors including "not implemented".
- Postgres: a replication=database walsender accepts plain SQL only over the simple protocol, so use `pgconn.Exec`, never parameterised `pgx` queries.
- Postgres: after `StartReplication` fails, pglogrepl leaves `ReadyForQuery` unread; reconnect instead of reusing the connection. The slot can stay active briefly after a killed backend, so `ErrSlotActive` is retryable on reconnect and fatal at first start (the caller starts the first source, T6.2).
- Postgres: `pglogrepl.SendStandbyStatusUpdate` replaces a flush or apply LSN of 0 with the write position and would confirm unhandled WAL, so `NewStandby` rejects a zero start; seed it with `SlotInfo.ConfirmedFlushLSN`. `StartStream` still takes 0 to resume from the slot.
- Postgres: pgconn is not safe for concurrent use; `Standby.Run` is the single goroutine that receives (with a deadline so the timer fires) and writes. `ReceiveMessage` after a timeout loses no data; copy `WALData`, since pgconn reuses its buffer.
- Postgres: `START_REPLICATION` does not fail for a missing publication; pgoutput warns (55000) and then streams nothing, so `Standby.Run` ends with `ErrPublicationMissing` on that notice. The replication scanner has no `E''` strings, so quote option values with `''` doubling only (`replLiteral`); SQL statements use `quoteLiteral`.
- Postgres: `Conn.Connect` (so Reconnect) pins datestyle, bytea_output, extra_float_digits and intervalstyle with `sessionSettings`, because the walsender text output follows database and role defaults; add a SET there when decode starts depending on another output setting.
- Postgres: send multi-statement DDL as one simple-protocol query so it runs in one transaction. A hand-added row filter or column list on a published table counts as drift.
- Postgres: `FOR ALL TABLES` needs superuser, also on 18. With `publish_via_partition_root`, `pg_publication_tables` lists the root table. `auto_alter` never switches between `FOR ALL TABLES` and a table list.
- Postgres: with REPLICA IDENTITY FULL the old tuple of an update carries the full TOAST value (recorded by `TestReplicaIdentityFullToastIntegration`), while the new tuple has `'u'` (`event.Unchanged`); so Before holds the value and After does not.
- Postgres: `recordFixture` runs `dml` as one simple-protocol query, so its statements share one implicit transaction; end each with `COMMIT;` and start the next with `BEGIN;` to record separate commits.
- Postgres: `TxBuffer` numbers `seq` from 1 over raw DML events (a truncate counts once per relation). pglogrepl returns commit times in the local zone, so `TxBuffer` converts to UTC.
- Postgres: `Conn.Reconnect` retries until ctx ends, except fatal errors (`isFatalConnect`: `ErrUnsupportedVersion`, SQLSTATE class 28 or 3D, URL parse errors), which return at once; never `event.Permanent`. The `onReset` hook must call `Relations.Reset` and `TxBuffer.Reset`. Connect defaults to a 10s timeout, and `IdentifySystem` and `pgConn.SendStatus` are bounded by deadlines.
- Postgres: `TxBuffer` caps a transaction by raw tuple bytes (`postgres.max_tx_bytes`, not a memory limit) and event count (`postgres.max_tx_events`, 0 = unlimited). Overflow returns a `*TxTooLargeError`, deliberately not `event.Permanent`: `on_permanent_error: skip` would silently drop the whole transaction.
- Postgres: the engine must stop on `*TxTooLargeError` without retry or confirm, and a restart hits the same transaction again until the limit is raised.
- Config: slot names are unique per server (host:port, scheme and credentials ignored) because slots are cluster-wide; publication names per server and database; table names per database.
- Config: yaml decode errors carry only a line, so a line with several keys (flow style) is reported without a key name.
- Postgres: record decode fixtures with `WALX_RECORD_FIXTURES=1 go test -run TestRecordFixtureIntegration ./internal/postgres` (writes `testdata/*.json` via `pg_logical_slot_get_binary_changes`, session pinned to UTC); unit tests decode the stored files.
- Postgres: under REPLICA IDENTITY FULL the Relation message flags every column as key, so `DecodeDML` falls back to the whole row; `ReadKeys` (keys.go) builds the `keys` map at startup (configured `key`, else primary key in index order only for REPLICA IDENTITY FULL tables, so a primary key outside another identity index cannot fail a delete; no entry without a key). Call it after `EnsureReplicaIdentity` and pass it to `NewTxBuffer`, or a FULL table's Key is the whole row.
- Postgres: `EnsureReplicaIdentity` (startup, after `EnsurePublication`) and `IdentityPolicy.CheckRelation` (runtime, via `WithIdentityCheck` on `TxBuffer`) share one `assess`. A listed table needs f for fsm_column, `on_change` (default identity sends no old row when the key is unchanged, so Before is nil, `Changed()` is false and the filter would drop every update), where on deletes, or a custom key outside the identity columns on a delete-enabled table; update or delete ops need a key (d with key, i, or f). Alter only tables not yet f, in one simple-protocol batch (one implicit transaction) that starts with `SET LOCAL lock_timeout` (`replicaIdentityLockTimeout`, 10s, so the ACCESS EXCLUSIVE lock cannot hang startup; SET LOCAL does not leak to the connection), and only when nothing is unfixable. SQLSTATE 55P03 maps to an `ErrReplicaIdentity` error saying another transaction holds a lock. Messages show `alterStatements` (no SET LOCAL). Opt-out, a keyless listed table, or no ownership fail with `ErrReplicaIdentity` (fatal); tables the config does not list (FOR ALL TABLES) only warn, since an insert-only keyless table is harmless. Runtime key columns are the Relation columns flagged 1.
- Engine: `pglogrepl.Parse` panics on an empty payload, so `decodeMessage` guards `len(WALData)==0`. The `send`, `confirm`, `empty`, `decode`, `sleep`, `jitter` and `timer` func fields on `Engine` are test seams (fakes, crash hooks); production wiring is in `New`. An empty retry policy behaves as `stop` in the engine; config defaults supply `forever`.
- Engine: reconnect is `Config.NewSource(ctx, resume)` (nil = a Source error ends `Run`). The factory must call `Conn.Reconnect` (closes the old conn, resets relations), `EnsureSlot` with autoCreate false (a recreated slot would silently skip the WAL lost with the dropped one), `StartStream(resume)`, and `NewStandby` seeded with `max(slot ConfirmedFlushLSN, resume)`. `resume` is the highest LSN the engine confirmed (0 before any), so only the discarded partial transaction is redelivered. The engine drains queued and in-flight batches first (the dead source cannot take their confirms), resets `Buffer`, then retries the factory with the retry backoff (doubling; reset once a stream delivers a message), logging `reconnecting` with attempt, err and `resume_lsn`. `postgres.IsFatal` errors (auth, version, `ErrSlotMissing`/`ErrSlotLost`, `ErrPublicationMissing`, `*TxTooLargeError`) and `event.Permanent` stop `Run`; anything else, `ErrSlotActive` included, is retried until ctx ends. Confirms go through `e.cur`, so a late confirm never reaches a dead source; Standby never lowers its LSN. A decode error cannot wait for `Source.Run` (the run context is cancelled after it returns), so source goroutines are tracked in `srcRuns`.
- Engine: supervisor fail fast: any pipeline return cancels the rest and all are awaited (in-flight calls finish). The first error wins; Canceled after the supervisor cancelled is induced and never masks it. A nil or Canceled return while ctx is still live is an error (`stopped unexpectedly`), and so is an error wrapping Canceled returned then. Parent cancel returns `ctx.Err()`; T6.2 maps Canceled to exit 0 and other errors to exit 1, and builds `engine.Config` from config (OnPermanentError, Retry, ShutdownTimeout, Metrics).
- Sink: `sink.Registry` (`internal/sink/sink.go`) maps `sink.type` to a `Factory(database, SinkConfig)`; sink packages never import `internal/sink`, the cmd wiring (T6.2) registers them, and an unknown type is `ErrUnknownType`. Every sink package runs `sinktest.Run(t, newTarget)` (`internal/sink/sinktest`) with a `Target` (sink, `Written` read-back of durable IDs, optional `Break` and `Unwritable` for the retryable and Permanent cases); `sinktest.Fake` is the reference.
- Filter: `where` reads After (Before for deletes; snapshot After; truncate always passes) and `on_change` applies to updates only. An `Unchanged` After value is read from Before for `where`; any other Unchanged never matches. Numbers compare by value across Go types (YAML `int` vs decoder `int64`).
- Filter: `fsm_column` needs no chain code (events are never collapsed, each update keeps its own ID and Before/After); config rejects it inside `drop_columns`, since the event must carry the state. T4.6 `reference_only` must keep it in After.
- Filter: `where` compares a string row value (numeric columns decode to strings) with a configured number by exact decimal value, so a text column holding "5" also matches `where: {c: 5}` (events carry no column types). An update whose where column is an unchanged TOAST value drops under the default identity (Before is nil); only REPLICA IDENTITY FULL fixes it, and auto-set covers `where` for deletes only.
- Filter: `filter.Chain.Apply` is the `engine.Filter`; `filter.New` takes the database name (metrics label `database`). `OpSnapshot` always passes for listed tables.
- Engine: `withPermanent` wraps `withRetry`; skip returns nil so `deliver` confirms `EndLSN`; only `event.Permanent` is skippable; `events_skipped_total` counts events with label `database`. Skip mode logs full event payloads at error level (data in logs); cover this in the T6.3 docs.
- Engine: idle advance runs on the reader goroutine: `keepalive` confirms the server WAL end only when `pending == 0` (batches queued or in flight, incremented by the reader before queueing, decremented by `deliver` after confirm) and `!TxBuffer.InTx()`. Empty batches are confirmed by `deliver` via `confirmEmpty` so they stay in order after earlier batches. `Standby.Keepalives()` is a one-slot latest-wins channel and `Source` requires it (nil is fine for fakes). pgoutput emits no Begin/Commit for transactions touching no published table, so only keepalives advance the LSN for them.
- Engine: `sink.timeout` (config, per database; `Config.SinkTimeout`) is opt-in, default 0 = no deadline on the sink ctx, because delivery is at-least-once: a timed-out call is retried and a late success becomes a duplicate that consumers dedupe by `Event.ID`. `withSinkTimeout` sits inside `withRetry`, so each attempt gets its own deadline and an expiry is an ordinary retryable `context.DeadlineExceeded` (never `event.Permanent`, never confirmed, not `ErrShutdownTimeout`). It still applies during shutdown, so an in-flight call ends at the earlier of the two timeouts. A sink that ignores its ctx is not bounded by it.
- Engine: `Run` owns closing the sink (exactly once); `main` must not. The sink's `Send` ctx is not the run ctx: a cancel lets the in-flight call finish, bounded by `shutdown_timeout` (default 30s), then `ErrShutdownTimeout` without confirm (Close then runs unawaited). Queued batches are not sent after cancel and retry backoff ends on cancel. The Source ctx outlives the run ctx until the deliverer returns, so Standby's final status update carries the last confirm. `Run` may return before an abandoned sink goroutine and an unawaited `Close` finish; a sink error arriving after a stop is returned, not `context.Canceled` (a stop during retry backoff does return Canceled). A test sink waiting on its own ctx needs the fake `e.timer` or a release channel, since that ctx never ends on cancel.
- Engine tests: a `confirm` crash hook must delegate to the original until the batch under test reached the sink, since `confirmEmpty` and idle keepalives also call `confirm`. To restart on the same slot, close the first `Conn` and wait for `pg_replication_slots.active` to turn false, else `ErrSlotActive`. Slot names must be lowercase (uppercase gives a misleading "slot does not exist"). Check a crash test by mutation: if the hook also calls the original, the redelivery test must fail.
- Tests: a fake must not close a channel a feeder goroutine may still send on (panic); close only from the sender or leave it open.
- Postgres tests: `pg_stat_replication.application_name` is empty for walx; join `pg_replication_slots.active_pid = pg_stat_replication.pid` to find its walsender.
- Postgres: `CheckWALRetention` returns warnings (`max_slot_wal_keep_size` = -1, `idle_replication_slot_timeout` = 0; a setting missing on the server is skipped), read from `pg_settings`. The caller must log them at startup; wiring is pending (T6.2). Its integration test changes both through `setServerSetting`.
- Postgres: `CheckKeys` (startup, T4.6) fails with `ErrKey` on a missing table or key column and warns when no usable unique index has all its key columns (not INCLUDE columns) inside the key; usable means valid, no predicate or expression, and primary, NULLS NOT DISTINCT or all columns NOT NULL (NULLs do not enforce uniqueness). The uncovered-identity check for delete-enabled tables is `EnsureReplicaIdentity`, not repeated there.
- Filter: `reference_only` runs last in `Chain.Apply` (`filter/key.go`): Before and After are nil, Key stays, and After holds only the `fsm_column` value (After, else Before when Unchanged; none on a delete).
- Sink: `internal/sink/jsonl.Encode` is the shared JSON-lines encoder (stdout and file sinks). `internal/sink/stdout` takes an `io.Writer` (`New`; `Factory` writes `os.Stdout`) and never closes it. `Send` encodes the whole batch first (an unencodable event, e.g. NaN, is `Permanent` with nothing written), then does one `Write`; a write error is plain and retried, so a partial write can repeat lines (dedupe by `Event.ID`). HTML escaping is off. Golden output lives in `testdata/*.golden` (goldie; refresh with `-update`).
- Sink: `internal/sink/file` appends to `sink.path` (`O_APPEND|O_CREATE`, mode 0o644 so a shipper under another user can read it; umask applies). `Factory` opens the file at startup, so an unwritable path fails there naming the path. `Send` does one `Write` then `Sync` and returns nil only after the fsync; `New` takes a `File` (`io.WriteCloser` + `Sync`) as the test seam. A failed write or fsync is plain and retried; the failed attempt may leave lines or a torn last line (a failed partial write makes the next `Send` start with a newline so the torn line cannot swallow a good one), so consumers must dedupe by `Event.ID` and skip a bad line. `Close` closes the file once; `Send` after it errors.

## Commands

```
go build ./...
go vet ./...
go test -race -cover ./...
go test -race -run TestName ./internal/event/
```

Integration tests need a Postgres 18 with `wal_level=logical` and skip unless `WALX_TEST_POSTGRES_URL` is set, so a green `go test` does not mean they ran. They know nothing about how it is run; `compose.dev.yaml` is one way (`docker compose -f compose.dev.yaml up -d --wait`, port 5432, then `WALX_TEST_POSTGRES_URL=postgres://walx:walx@localhost:5432/walx?sslmode=disable`). Use goleak for goroutine-leak checks.
Run engine tests with `-timeout 120s`: a test sink returning a plain error under policy `forever` retries forever.
Each test gets a throwaway database; tests must drop cluster-wide objects (roles, physical slots) themselves. Change server-wide settings only through `setServerSetting`, which refuses a customised value and resets it afterwards; engine integration tests set `wal_sender_timeout` through `setDatabaseSetting` (ALTER DATABASE on the test database) instead. If compose runs on a remote Docker context, forward the port locally. On macOS use `python3` or `gofmt` for in-place edits (BSD `sed -i` needs a suffix).

## Conventions

- Tests first, run with `-race`.
- Every exported Go identifier gets a short doc comment starting with its name; comment unexported ones only when the why is non-obvious.
- Go files: one concern per file, named after it (`sink.go`, `lsn.go`); at most one interface per file.
- Within a file: type, constructor, methods, then unexported helpers. Keep tests in a matching `_test.go`.
- Install dev tools as Go tools (`go get -tool`), not globally.
- Testify: prefer `require` over `assert`.
- Write every test table-driven, even with one case.
- Preferred tools: testify, goldie, tack, mockery, task.

## Commit messages

[Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/#specification): `<type>[scope][!]: <description>`. Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`. Description short, lowercase, imperative, no trailing period. Mark breaking changes with `!` and/or a `BREAKING CHANGE:` footer.

Never mention the plan (task IDs like `T4.5`, milestones like `M4`, "the plan") in a commit title or body: readers of the history do not have the plan. Describe the change itself.
